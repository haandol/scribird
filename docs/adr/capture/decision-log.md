# Decision Log: capture

이 문서는 capture 카테고리의 **주요 결정 변경 이력**이다. 각 ADR 본문은 현재
상태만 서술하고, "무엇이 왜 바뀌었나"의 시간축은 여기에 역순으로 쌓는다. 개별
diff 는 Git 이 보존한다.

## 2026-08-21 — 마이크 음소거 단축키를 설정에서 바꿀 수 있게 한다

- **현재 ADR**: [per-source-failure-isolation](./0003-per-source-failure-isolation.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 앱 포커스 중 `⌘Y`로 고정된 마이크 음소거 토글 → 기본값은 `⌘Y`로
  유지하되 설정에서 바꾸고 초기화할 수 있으며 앱 재시작 후에도 선택을 유지한다.
- **왜**: 고정 조합이 다른 Scribird 단축키나 사용자 환경과 충돌하면 마이크 음소거
  기능을 쓸 수 없다. 전역으로 넓히지 않고 로컬 범위를 유지하면서 충돌을 피할 수 있어야 한다.
- **유지되는 것**: 녹취 중 마이크 소스가 살아 있을 때만 동작하고, 시스템 출력의
  캡처·전사·합본·레벨에는 영향을 주지 않는다.

## 2026-08-21 — 앱 포커스 중 `⌘Y`로 마이크 음소거를 토글한다

- **현재 ADR**: [per-source-failure-isolation](./0003-per-source-failure-isolation.md)
- **변경 유형**: 요구사항 규칙 추가 (major)
- **무엇이**: 전사 화면 버튼만으로 마이크 음소거를 바꿨다 → 버튼과 함께 Scribird가
  포커스를 가진 동안 `⌘Y`로 같은 상태를 토글한다.
- **왜**: 회의 중 마우스로 음소거 버튼을 찾지 않고 즉시 자기 음성을 제외할 수 있어야 하며,
  다른 앱의 단축키까지 가로채는 전역 등록은 필요하지 않다.
- **유지되는 것**: 음소거는 마이크 소스에만 적용하고 시스템 출력 캡처·전사·합본·레벨은
  계속 유지한다. 마이크 장치도 시간축 보존을 위해 열어 둔다.

## 2026-08-20 — 녹취 중 마이크 음소거 상태를 추가

- **현재 ADR**: [per-source-failure-isolation](./0003-per-source-failure-isolation.md)
- **변경 유형**: 아키텍처
- **무엇이**: 독립 캡처 소스에 마이크 전용 음소거 상태를 추가하고, 음소거 구간은 전사와 원본 저장 양쪽에서 같은 길이의 무음으로 다룬다.
- **왜**: 회의 앱 내부 음소거는 직접 캡처하는 마이크에 적용되지 않으므로, 시스템 출력은 유지하면서 자기 음성만 확실히 제외할 경계가 필요하다.

## 2026-07-31 — 캡처 장치를 사용자가 고정할 수 있게 한다

- **현재 ADR**: [capture-device-change-follow](./0005-capture-device-change-follow.md)
- **변경 유형**: 요구사항 규칙 추가 (major)
- **무엇이**: 캡처 장치가 항상 시스템 기본을 따라갔다 → 시스템 기본 따라가기를 **기본값**으로
  두고, 사용자가 설정에서 장치를 고르면 그 장치에 고정한다. 선택은 소스별로 독립이고, 고른
  장치가 사라지면 기본으로 되돌리되 선택은 보존한다.
- **왜**: 시스템 기본이 사용자가 회의를 듣는 장치와 다를 수 있다. 실측에서 장치 목록에는 회의
  앱이 만든 가상 장치(`Microsoft Teams Audio`, `ZoomAudioDevice`)가 함께 있었고, 그중
  하나가 기본이 되는 구성이 존재한다. 그때 기본만 따라가면 잡는 대상이 의도와 어긋나는데
  사용자에게 바로잡을 수단이 없었다 — 시스템 설정을 바꾸면 회의를 듣는 경로까지 바뀌므로 회의를
  희생해야 한다. 마이크도 같다: 여러 마이크 중 품질 좋은 것을 고르고 싶어도 기본에 묶였다.
  따라가기를 버리지 않은 이유는 그것이 안전한 기본값이기 때문이다 — 아무 설정도 하지 않은
  사용자가 이어폰을 껴도 캡처가 따라와야 한다.
- **측정으로 좁혀진 것**: 장치 식별자를 장치로 되찾는 API가 **존재하지 않는 식별자에도
  `status=0`을 반환하고 장치 번호 `0`을 줬다**. 캡처에서 지키던 "성공 반환을 증거로 믿지
  않는다"가 여기에도 적용된다. 또 장치 목록은 입력 전용·출력 전용·양방향이 섞여 있어(실측 7개
  장치 중 입력 전용 3, 출력 전용 2, 양방향 2), 소스별로 채널 수로 걸러야 한다.

## 2026-07-31 — 기본 장치 변경을 따라가기로 한다

- **현재 ADR**: [capture-device-change-follow](./0005-capture-device-change-follow.md)
- **변경 유형**: 새 결정
- **무엇이**: 캡처가 시작 시점의 장치에 끝까지 묶여 있었다 → 기본 장치가 바뀌면 영향받은
  소스의 캡처만 새 장치로 옮긴다. 세션 경계는 만들지 않으므로 회의록·원본 오디오·시간축이
  이어진다.
- **왜**: 회의 직전에 이어폰을 끼는 것이 통상적인 순서인데, 그때 탭은 이제 아무것도 나오지
  않는 내장 스피커를 계속 잡아 상대방 발언이 통째로 비었다. 더 나쁜 것은 기존 무음 판정이
  이 상황을 권한 문제로 오진해 사용자를 이미 허용한 권한 설정 화면으로 보냈다는 점이다 —
  조용한 실패를 드러내려고 만든 장치가 틀린 원인을 가리켰다.
- **측정으로 좁혀진 것**: 기본 출력 셀렉터가 둘이고 서로 독립적으로 움직인다
  (`sysOut`만 바꾸면 `sysOut=106 / defOut=94`로 갈라짐). 각 리스너는 자기 셀렉터에만
  발화하므로, 탭이 쓰는 셀렉터를 감시하지 않으면 알림이 아예 오지 않는다. 또한
  `AudioObjectRemovePropertyListenerBlock`이 `status=0`을 반환하고도 리스너를 떼지
  않았다(해제 3회 반복·블록 고정 모두 동일). 캡처에서 이미 지키던 "성공 반환을 증거로
  믿지 않는다"가 감시 해제에도 적용된다.
