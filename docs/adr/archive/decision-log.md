# Decision Log: archive

이 문서는 archive 카테고리의 **주요 결정 변경 이력**이다. 각 ADR 본문은 현재
상태만 서술하고, "무엇이 왜 바뀌었나"의 시간축은 여기에 역순으로 쌓는다. 개별
diff 는 Git 이 보존한다.

## 2026-08-21 — 소스별 원본 대신 녹음 중 모노 합본 하나를 저장

- **현재 ADR**: [original-audio-format](./0002-original-audio-format.md)
- **변경 유형**: 아키텍처
- **무엇이**: 마이크와 시스템 출력을 리샘플링 전 별도 M4A로 저장한다 → 두 캡처를
  공통 시간축에 배치해 녹음 중 모노 `meeting.m4a` 하나로 합성하고 별도 소스 파일은
  만들지 않는다.
- **왜**: 별도 파일은 독립 캡처의 시작 시차와 장치 전환 공백을 사후에 정확히 복원할
  기준이 없고, 시스템 출력과 마이크 각각에도 여러 실제 화자가 섞일 수 있어 소스 분리가
  실제 화자 분리를 보장하지 않는다. 사용자는 실제 회의처럼 재생하고 범용 전사기에 바로
  넣을 수 있는 파일 하나를 우선한다.
- **무효가 된 것**: 네이티브 포맷과 소스별 화자 정보를 원본 파일로 보존해 미래 재처리에
  사용한다는 목표. 합본 이후에는 소스별 재처리와 독립 볼륨 조정이 불가능하다.

## 2026-08-20 — AAC 미지원 캡처 포맷에 ALAC fallback을 추가

- **현재 ADR**: [original-audio-format](./0002-original-audio-format.md)
- **변경 유형**: 채택 대안 교체
- **무엇이**: 모든 캡처 포맷을 채널당 AAC 128k로 저장한다 → 검증된 44.1/48kHz는
  AAC 128k를 유지하고, 그 외 포맷은 네이티브 샘플레이트 ALAC로 저장한다.
- **왜**: Bluetooth 통화 모드의 16~32kHz와 96kHz 캡처에서 Apple AAC 인코더가 파일
  생성 뒤 쓰기 또는 마무리를 거부해 원본 파일만 저장되지 않았다. 비트레이트를 낮추면 이미
  측정된 재전사 오인식 위험을 다시 열고, 모든 장치를 무손실로 저장하면 일반 장치에도
  2.6배의 용량 비용을 부과한다.

## 2026-08-05 — 저장 위치를 고정에서 사용자 선택으로 열었다

- **현재 ADR**: [transcript-root-location](./0004-transcript-root-location.md)
- **변경 유형**: 채택 대안 교체 (major)
- **무엇이**: 저장 루트를 코드가 정하고 바꿀 수 없었다 → 사용자가 고를 수 있게 하고, 정하지
  않으면 기존 기본 위치를 쓴다. 고른 폴더를 쓸 수 없으면 세션을 접지 않고 기본 위치로 되돌려
  녹취를 진행하되 사유를 알린다. 되돌려도 선택은 보존하고, 이미 저장된 산출물은 옮기지 않는다.
- **왜**: 위치가 고정이면 앱 밖에서만 풀 수 있는 요구가 세 가지 남는다 — 동기화 폴더에 두어
  다른 기기에서 보기, 문서 폴더가 동기화 대상인 환경에서 회의당 100MB가 넘는 원본을 올리지 않기,
  민감한 회의를 암호화 볼륨에 두기. 앱 밖의 해결은 사용자가 회의마다 기억해야 하는 절차이고,
  잊으면 그 회의록은 한 기기에만 남는다.
- **무효가 된 것**: 위치 선택을 "이 문제와 다른 문제를 푼다"며 미뤄 둔 판단. 산출물을 못 찾는
  문제와는 여전히 별개이지만, 별개라는 것이 다루지 않을 이유는 아니었다. 위치를 고정으로 두어
  얻던 "실패 모드가 없다"는 성질도 함께 사라졌다 — 부재·쓰기 불가를 되돌림으로 다룬다.

## 2026-08-04 — 화면에 보인 발화가 산출물에 없을 수 있었다

- **현재 ADR**: [transcript-durability](./0001-transcript-durability.md)
- **변경 유형**: 동작 바꾸는 버그 수정 (major)
- **무엇이**: 확정 발화를 화면에 반영한 뒤 디스크 기록을 **분리된 비동기 작업으로 미뤘고**,
  종료 경로는 그 작업들을 기다리지 않고 읽기용 회의록을 생성하고 세션을 닫았다 → 확정 발화의
  기록을 화면 반영과 같은 순서에 묶고, 읽기용 회의록 생성 전에 기록이 모두 끝나 있게 한다.
  세션이 닫힌 뒤 도착한 확정 발화도 조용히 버리지 않는다. 계약에 "화면에 보인 발화는 반드시
  산출물에 있다"를 명시했다.
- **왜**: 사용자가 화면에서 전사된 문장을 읽었는데 두 산출물 어디에도 없는 경우가 보고됐다.
  원인은 미뤄진 기록 작업이 세션이 닫힌 뒤에 실행되는 것이다. 그때 append는 이미 닫힌 파일
  핸들 때문에 조용히 버려지고, 읽기용 회의록은 그 발화가 반영되기 전 목록으로 이미 생성돼 있어
  **두 형식에서 함께 빠진다** — 즉시 기록이 담당하던 이중화가 이 순서에서는 작동하지 않는다.
  화면에는 있는데 파일에는 없는 상태는 단순 누락보다 나쁘다: 기록됐다고 믿을 근거를 앱이 직접
  제공한 뒤 지키지 않은 것이고, 회의는 한 번 일어나고 끝나므로 되돌릴 수 없다.
- **측정으로 좁혀진 것**: 같은 순서를 재현한 프로브에서 **200회 중 200회 유실**됐다. 화면에
  5개가 표시된 시점의 저장분이 0개였다 — 미뤄진 작업이 하나도 시작되지 않은 채 세션이 닫혔다.
  즉 경합이 드물게 지는 문제가 아니라 기본적으로 지는 순서였고, 짧은 발화가 세션 끝에 몰릴 때
  사용자에게 드러났다.
- **무효가 된 것**: "크래시로 읽기용 회의록을 잃어도 즉시 기록에서 복원할 수 있다"는 이중화가
  이 경로에서는 성립하지 않았다는 점. 순서를 고쳐 그 전제를 복구했다.

## 2026-08-04 — 산출물 위치를 회의 중 보여주고 종료 시 자동으로 연다

- **현재 ADR**: [session-output-discoverability](./0003-session-output-discoverability.md)
- **변경 유형**: 새 결정
- **무엇이**: 산출물이 어디에 저장되는지 화면에 나타나지 않았고, 저장 폴더를 여는 것은
  마무리된 세션이 있을 때만 나타나는 버튼이었다 → 저장 위치를 전사 화면에 **항상** 표시하고
  눌러서 열 수 있게 한다. 가리키는 대상만 상태에 따라 바뀐다 — 녹취 중이면 현재 세션, 종료
  후면 직전 세션, 녹취한 적이 없으면 저장 루트. 그리고 녹취를 종료하면 저장 폴더를 자동으로
  연다. 자동 열기는 설정에서 끌 수 있고 기본값은 켬이며, 세션 경계에서는 열지 않는다.
- **왜**: 이 앱은 메뉴바와 좁은 창으로 쓰이므로 산출물 위치를 볼 다른 화면이 없었다. 그래서
  사용자가 **녹취가 실제로 저장되고 있는지 확인할 수단이 없었고**, 회의는 한 번 일어나고
  끝나므로 저장되지 않았다는 사실을 나중에 알아도 되돌릴 수 없다. 폴더를 여는 버튼은 이미
  있었지만 눌러야 한다는 것을 알아야 했고, 산출물을 못 찾는 사용자는 그 버튼의 존재를 모르는
  사용자다. 회의 직후는 회의록을 확인하는 시점이므로 확인을 기본 동작으로 옮겼다.
  **표시를 사라지지 않게 한 것도 같은 이유다** — 조건에 따라 나타나는 버튼은 사용자가 그
  존재를 학습하지 못하게 만들고, 산출물이 어디에 저장되는지는 첫 녹취를 시작하기 전에도 알고
  싶은 것이다. 아직 산출물이 없다는 것이 위치를 감출 이유는 되지 않는다.
- **경계 조건**: 세션 경계에서는 열지 않기로 했다 — 경계를 끊는 것은 회의를 계속하겠다는
  뜻이라 산출물을 확인할 시점이 아니고, 여러 번 끊으면 그만큼 창이 열려 회의 화면을 가린다.
  폴더 열기 실패는 종료를 실패로 만들지 않는다: 산출물은 이미 디스크에 있고 여는 것은 편의
  기능이므로, 실패로 보고하면 저장된 회의록을 잃은 것처럼 보인다.
