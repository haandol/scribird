# Decision Log: session

이 문서는 session 카테고리의 **주요 결정 변경 이력**이다. 각 ADR 본문은 현재
상태만 서술하고, "무엇이 왜 바뀌었나"의 시간축은 여기에 역순으로 쌓는다. 개별
diff 는 Git 이 보존한다.

## 2026-08-21 — 기본 회의 언어를 English로 두고 필수 모델을 시작 시 확보한다

- **현재 ADR**: [settings-surface-separation](./0003-settings-surface-separation.md)
- **변경 유형**: 요구사항 값 변경
- **무엇이**: 기본 회의 언어가 한국어+English였다 → English이며, 필수 English Speech
  에셋이 없으면 앱 시작 시 macOS 설치를 자동으로 시작한다. 버전 조회는 계속 사용자 요청
  시에만 실행된다.
- **왜**: English는 앱이 항상 제공해야 하는 기본 전사 언어라 첫 실행에서 설정을 찾아 설치해야
  하는 상태를 허용하지 않기로 했다.
- **무효가 된 것**: 사용자가 요청하지 않은 네트워크 통신은 어떤 종류도 없다는 설명. 현재는
  회의 데이터를 보내지 않는 macOS English Speech 에셋 설치만 시작 시 예외다.

## 2026-08-06 — 회의 언어를 전사 화면에서도 바꾼다

- **현재 ADR**: [settings-surface-separation](./0003-settings-surface-separation.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 회의 언어는 설정 창에서만 바꾸고 전사 화면은 그 값을 읽기만 했다 → 두 화면
  모두에서 바꿀 수 있다. 전사 화면에 남기는 것 목록에 회의 언어가 추가됐고, 이 항목을 녹취 중
  잠기는 항목으로 분류한 서술도 사라졌다.
- **왜**: 이 값이 틀렸다는 것을 발견하는 화면이 전사 화면이다 — 신호가 빠진 발화로 나타나기
  때문이다. 발견은 이 화면에서 하고 수정은 다른 창에서 하게 두면 회의 중에 창을 옮겨야 하고,
  그 값이 녹취 중에 바뀔 수 없다는 전제가 사라지자 옮길 이유도 없어졌다. 설정 창에도 같은 항목을
  남긴 것은 회의 전에 정하는 경로가 필요하기 때문이다 — 한쪽만 두면 각각 잃는 것이 분명하다.
- **무효가 된 것**: "언어 구성을 두 곳에서 다룬다 — 설정에서 바꾸고 전사 화면에서 읽는다"는
  대가. 이제 양쪽에서 바꾸므로 한쪽의 변경이 다른 쪽에 즉시 보여야 하고, 전환이 실패하면 두
  화면 모두 사용자가 고른 값이 아니라 실제 유효한 구성을 보여야 한다.

## 2026-08-04 — 전사 창은 사용자가 부른 창을 덮지 않고, ⌘W로 닫힌다

- **현재 ADR**: [global-hotkey-floating-window](./0002-global-hotkey-floating-window.md)
- **변경 유형**: 요구사항 규칙 추가 (major)
- **무엇이**: 전사 창이 항상 다른 모든 창 위에 있었다 → **위에 머무는 것과 앞을 가로막는 것을
  구분한다.** 앱이 스스로 다른 창을 앞으로 내보내는 동작을 할 때는 그 창이 전사 창보다 앞에
  온다. 그리고 창을 닫는 수단에 표준 단축키(`⌘W`)를 더했다.
- **왜**: 녹취를 끝내면 산출물 폴더를 열어 주는데, 전사 창이 그 위를 덮어 **폴더를 열어 준
  목적이 사라졌다.** 원인은 "다른 앱 위에 머문다"를 창 레벨 하나로 구현한 것이다. 그 성질이
  필요한 상대는 사용자가 배경에 두고 참여하는 회의 앱인데, 사용자가 직접 불러낸 창까지 같이
  덮었다 — 부른 것을 덮으면 부르지 않은 것과 구분되지 않는다. 닫기 단축키는 같은 결의 문제다:
  자동으로 닫히지 않는 창이므로 치우는 수단이 창에 있어야 하고, 이 플랫폼에서 창을 닫는 조작은
  `⌘W`이므로 사용자가 이미 아는 것을 다시 배우게 할 이유가 없다.
- **의도된 대가**: 앱이 부른 창에 앞자리를 넘기는 동안 전사 창이 회의 화면에 덮일 수 있다.
  "확인용 화면이 가려지지 않는다"와 "사용자가 부른 것을 보여준다"가 부딪히는 지점이고 후자를
  택했다.

## 2026-08-04 — 설정 항목이 모두 녹취 중 잠기는 것은 아니다

- **현재 ADR**: [settings-surface-separation](./0003-settings-surface-separation.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: "녹취 중에 바뀐 값은 없다"를 계약에 적어 두었다 → 잠금의 근거("이미 만들어진
  전사기와 열려 있는 파일에 반영되지 않는다")가 없는 항목은 잠그지 않는다. 설정 창 항목으로
  종료 시 저장 폴더 자동 열기가 추가됐고, 이 값은 종료 시점에만 읽히므로 녹취 중에도 바꿀 수
  있다. 전사 화면에 남기는 것 목록에도 현재 세션의 저장 위치가 추가됐다.
- **왜**: 잠금을 항목이 아니라 창 전체의 성질로 적어 둔 것이 실제와 어긋났다. 캡처 장치는
  이미 녹취 중에 바꿀 수 있었고(장치를 잘못 골라 회의가 비는 것을 발견하는 시점이 회의 중이라
  그때 고칠 수 없으면 목적을 잃는다), 새로 추가한 자동 열기도 잠글 이유가 없다. 잠글 근거가
  없는 항목을 잠그면 회의 중에 발견한 문제를 고칠 수 없게 된다. 저장 위치를 전사 화면에 둔
  이유는 그것이 설정값이 아니라 진행 중인 세션의 상태이기 때문이다 — 세션마다 바뀌고, 녹취가
  실제로 저장되고 있는지 확인하는 근거다.

## 2026-07-31 — 설정을 여는 단축키를 사용자가 바꿀 수 있게 한다

- **현재 ADR**: [settings-surface-separation](./0003-settings-surface-separation.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 설정을 여는 단축키가 `⌘,` 고정이었다 → 기본값은 `⌘,`이고 사용자가 바꿀 수 있다.
  이 단축키는 전역이 아니며 전사 창이 앞에 있을 때만 듣는다는 점도 계약에 명시했다.
- **왜**: 다른 앱이 `⌘,`를 전역으로 점유하면 이 앱 안에서는 이길 방법이 없다. 실측으로 확인했다 —
  메뉴바 유틸리티가 `⌘,`를 전역 등록한 환경에서 앱이 반응하지 않았고, 그 유틸리티를 종료하자 즉시
  동작했다. 고정값으로 두면 그런 환경의 사용자에게는 없는 기능이 되고, 원인이 다른 앱이라는 것도
  알 수 없다. 전역 단축키를 바꿀 수 있게 한 것과 같은 판단이다.
- **함께 정정한 것**: 이 단축키를 SwiftUI의 `.keyboardShortcut`으로 붙여 두었는데 그것은 메뉴
  시스템을 거치고, 메뉴바 전용 앱에는 메인 메뉴가 없다(실측: `NSApp.mainMenu`가 nil). 즉 계약에
  적힌 `⌘,`가 애초에 동작하지 않는 상태였다. 창이 키 이벤트를 직접 받도록 고쳤다.

## 2026-07-31 — 설정 창의 모든 항목이 앱 실행 사이에 유지된다

- **현재 ADR**: [settings-surface-separation](./0003-settings-surface-separation.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 회의 언어와 음성 원본 저장 여부가 실행마다 기본값으로 돌아갔다 → 사용자가
  정한 값이 유지된다. "설정 창에 있는 모든 항목은 다시 켜도 유지된다"를 이 ADR 의 요구사항
  계약으로 명시했고, 기본값(한국어 + English / 원본 저장 켬)과 해석 실패 시 기본값 복귀도
  함께 계약에 넣었다.
- **왜**: 이 창의 정의가 "한 번 정하고 잊는 것"인데 두 항목이 유지되지 않아 정의와 모순됐다.
  단축키만 유지되고 나머지는 아니어서, 어느 항목이 유지되는지가 사용자에게 예측 불가능했다.
  손실이 조용한 것이 결정적이었다 — 원본 저장을 끈 사용자가 그것이 켜진 것을 모른 채 녹취하면
  남기지 않으려던 음성이 디스크에 남고, 단일 언어를 고른 사용자는 다중 언어로 되돌아간 것을
  모르고 코드스위칭 경계 손실을 겪는다. 둘 다 회의가 끝난 뒤에야 드러난다.

## 2026-07-30 — 전역 단축키 등록을 화면 생명주기에서 앱 시작 시점으로 옮긴다

- **현재 ADR**: [global-hotkey-floating-window](./0002-global-hotkey-floating-window.md)
- **변경 유형**: 동작 바꾸는 버그 수정
- **무엇이**: 단축키 등록이 메뉴바 팝오버 내용이 만들어질 때 일어났다 → 앱이 시작될 때
  일어난다. 그에 따라 "단축키는 앱이 시작된 시점부터 동작한다"를 지켜야 하는 계약으로
  본문에 명시했다.
- **왜**: 메뉴바 팝오버의 내용은 사용자가 팝오버를 처음 열 때 비로소 만들어진다. 그래서
  메뉴바 아이콘을 한 번 클릭하기 전까지 단축키가 동작하지 않았다. 이 단축키의 목적이
  화면에 도달하는 것이므로, 화면을 먼저 열어야 단축키가 준비되는 구조는 기능을
  무의미하게 만든다. 등록 실패가 아니라 등록 자체가 일어나지 않는 상태여서 기존 실패
  안내 경로로도 드러나지 않았다.
