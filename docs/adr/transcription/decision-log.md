# Decision Log: transcription

이 문서는 transcription 카테고리의 **주요 결정 변경 이력**이다. 각 ADR 본문은 현재
상태만 서술하고, "무엇이 왜 바뀌었나"의 시간축은 여기에 역순으로 쌓는다. 개별
diff 는 Git 이 보존한다.

## 2026-08-21 — 모델 설치 요청을 예약과 진행률 취소에서 분리했다

- **현재 ADR**: [model-provisioning-gate](./0003-model-provisioning-gate.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 설치 전에 로케일을 예약하고 진행률 정체 시 요청을 취소했다 → 설치 경로는
  예약하지 않고 시스템 요청의 완료·오류와 최종 설치 목록으로만 판정한다. 진행률과
  `.downloading` 지속 시간은 취소나 실패 근거로 쓰지 않으며, 예약은 설치된 모델로 세션을
  시작할 때만 수행한다.
- **왜**: 진행률 취소가 `transcription.ko` 구독을 해제해 이미 설치된 170,065,920바이트
  한국어 에셋을 현재 자산 세트에서 제거했다. 이후 시스템은 한국어가 필요한 3개 구성을
  요청받고도 영어와 메타데이터 2개만 가진 자산 세트를 7일 예약 작업으로 남겨 실제
  네트워크 전송을 시작하지 않았다.
- **무효가 된 것**: 진행률 정체 취소가 설치 요청만 끝내고 이미 설치된 모델에는 영향을
  주지 않는다는 가정과, 미설치 모델을 먼저 예약해야 다운로드 결과를 안전하게 지킨다는 가정.

## 2026-08-21 — 모델 설치의 0% 준비 단계를 정체에서 분리했다

- **현재 ADR**: [model-provisioning-gate](./0003-model-provisioning-gate.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 모든 진행률에서 30초간 변화가 없으면 설치를 취소하고 퍼센트를 표시했다 →
  화면에는 신뢰할 수 없는 퍼센트 대신 `다운로드 중`만 표시한다. 내부 진행률 `0%`는
  macOS의 자산 구성·대기열 준비로 보고 취소하지 않으며, 처음 `0%`를 넘은 뒤 30초간
  변하지 않을 때만 정체로 끝낸다.
- **왜**: 한국어 단독 설치 로그에서 시스템은 `0 / 0`, `downloading`을 보고하면서 기존
  자산 세트 작업을 취소하고 새 요청을 대기열에 넣고 있었다. 네트워크 전송은 아직 시작되지
  않았고 시스템 오류도 없었지만, 앱이 요청 30초 뒤 `transcription.ko` 구독을 해제해
  다운로드가 시작될 기회를 없앴다.
- **무효가 된 것**: `0%` 무변화를 실제 다운로드 정체로 해석하면 안전하다는 가정.

## 2026-08-21 — 모델 설치를 녹취 관문에서 언어별 설정 관리로 옮겼다

- **현재 ADR**: [model-provisioning-gate](./0003-model-provisioning-gate.md)
- **변경 유형**: 아키텍처
- **무엇이**: 녹취 시작과 회의 중 언어 전환이 필요한 모델을 자동으로 묶어 설치했다 →
  English는 앱 시작 시 없으면 자동 설치하고 한국어는 설정에서 설치·재시도한다. 녹취 화면에는
  설치된 언어와 가능한 조합만 표시한다. 진행률이 30초간 변하지 않거나 일부 에셋만 준비되면
  실패로 끝내고 화면 잠금을 푼다.
- **왜**: 여러 에셋 중 일부만 준비된 시스템 설치 요청이 `0%` 또는 `50%`에서 반환되지 않아
  녹취 시작 화면이 무기한 잠겼고, 어느 언어가 문제인지 구분하거나 이미 설치된 언어로 시작할
  수 없었다.
- **무효가 된 것**: 미설치 언어를 고르면 기존 언어로 전사를 계속하며 자동 다운로드한다는
  동작과, 여러 로케일 에셋을 한 요청으로 묶어 다운로드 횟수를 줄인다는 이점.

## 2026-08-06 — 회의 언어를 녹취 중에도 바꿀 수 있게 했다

- **현재 ADR**: [in-session-language-switch](./0004-in-session-language-switch.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 언어 구성이 세션 시작 시점에 고정돼 녹취 중에는 잠겼다 → 언제든 바꿀 수 있고,
  전환은 캡처·원본 오디오·회의록·시간축을 끊지 않는다. 미설치 언어는 기존 언어로 전사를
  계속하면서 내려받은 뒤 교체하고, 실패하면 기존 언어를 유지한다. 모델 확보 관문은 세션
  시작에만 적용되는 것으로 범위가 좁혀졌고, 세션 중 전환은 새 결정이 소유한다.
- **왜**: 언어 구성이 틀렸다는 신호는 화면에 빠진 발화로 나타나고 그 시점이 회의 중이다.
  잠긴 상태에서 사용자가 할 수 있는 것은 중지 후 재시작뿐인데, 그 경로는 한 회의를 두 산출물로
  쪼개고 재시작이 모델 확보 관문을 다시 통과하는 동안의 발화를 잃는다. 캡처 장치를 잘못 골랐을
  때 세션을 끊지 않고 그 소스만 다시 연결하기로 한 것과 같은 상황인데, 언어만 다르게 다룰 근거가
  측정에서 나오지 않았다.
- **측정으로 좁혀진 것**: **오디오 포맷이 언어 구성과 무관하게 같다** — 한국어 단독, 영어 단독,
  두 언어 동시 모두 `16000 Hz, 1ch, Int16, interleaved`였다. 그래서 언어 전환이 캡처
  파이프라인을 재구성할 이유가 없다. **분석기를 살려둔 채 전사기를 교체할 수 있다** — 오디오가
  흐르는 중 교체가 80밀리초에 끝났고, 한국어 발화 뒤 영어 전사기를 추가하자 직후 영어 발화가
  온전히 인식됐다(`ko [0.00~8.69]`와 `en [4.93~8.69]`가 함께 나왔다). **전사기는 무음을
  만나도 확정을 미룬다** — 발화 사이에 1.5초 무음을 넣어도 한국어 전사기가 13.14초까지 하나의
  세그먼트로 뭉갠 뒤에야 확정했다. 그래서 로케일을 떼어내면 진행 중인 한 문장이 아니라 그때까지의
  발화 전부가 사라진다(재현: 좁히기를 뺀 대조군에서는 그 발화가 확정됐고, 좁히기를 넣으면 결과에서
  사라졌다). **확정을 유도해 건지는 방식은 쓸 수 없다** — 캡처가 열린 상태의 마감 요청이 90초
  동안 반환되지 않았고, 이미 공급된 지점까지로 한정해도 10.4초 동안 반환되지 않아 녹취 전체가
  멈췄다. **그 시점의 잠정 결과에는 발화가 이미 담겨 있다** — 제거 직전 잠정 텍스트에 그때까지의
  한국어 발화가 온전히 들어 있었고, 화면에 보이던 것을 그대로 확정해 남기는 것으로 유실이 해결됐다.
  **미설치 로케일은 살아 있는 분석기를 죽인다** — 추가가 실패를 던진 뒤에도 모듈 목록이 오염된 채
  남았고, 원래 구성으로 되돌리는 교체는 성공을 반환하면서 복구하지 못했으며, 멀쩡했던 기존 언어의
  결과 스트림까지 같은 에러로 닫혀 진행 중 발화가 사라졌다. 그래서 사후 복구가 아니라 사전 확인만이
  안전하다.
- **무효가 된 것**: "언어 구성이 세션 중 잠기므로 예상과 다른 언어로 회의가 진행되면 녹취를
  중지하고 다시 시작해야 한다"는 대가. 대신 좁히는 전환에서 제거되는 언어의 마지막 기록이 거칠어지는
  대가가 새로 생겼다 — 확정 전 상태를 남기므로 그 언어가 뭉갠 구간이 남는 언어의 결과와 중복된다.

## 2026-08-05 — 산출물의 화자 이름을 화면 언어에서 떼어냈다

- **현재 ADR**: [source-based-speaker-attribution](./0001-source-based-speaker-attribution.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 화자 라벨을 한국어 표기(`나`/`상대방`)로 계약에 박아 두었다 → 소스가 화자를
  확정한다는 규칙만 이 결정에 남기고, 산출물에 적히는 표기는 화면 언어와 무관하게 한 벌이라는
  제약만 둔다. 구체적 표기는 화면 언어 결정이 정한다.
- **왜**: 화면 언어를 고를 수 있게 하면서 산출물 형식이 설정에 의존할지를 판정해야 했다. 회의록은
  한 폴더에 누적되고 재생성할 수 없으므로 설정에 따라 형식이 바뀌면 같은 폴더 안에서 어휘가
  섞이고, 그것을 읽는 도구는 어느 설정으로 만들어졌는지 알 수 없다 — 이 저장소의 화자 세분화
  도구가 정확히 그 처지가 된다. 표기를 이 ADR이 들고 있으면 두 결정이 같은 값을 각자 적는 상태가
  되므로, 한쪽만 고쳐지는 사고를 막기 위해 소유를 한 곳으로 옮겼다.

## 2026-08-04 — 예약 실패로는 녹취를 막지 않는다

- **현재 ADR**: [model-provisioning-gate](./0003-model-provisioning-gate.md)
- **변경 유형**: 요구사항 규칙 변경 (major)
- **무엇이**: 로케일 예약 실패를 곧 세션 실패로 접었다 → 실패하면 이번 세션이 쓰지 않는 잔여
  예약을 회수해 재시도하고, 그래도 실패하면 **필요한 모델이 이미 설치돼 있으면 경고와 함께
  녹취를 진행**한다. 미설치일 때만 세션을 접는다. 게이트를 닫는 유일한 사유는 오디오 포맷을
  얻지 못한 경우로 좁혀졌다. 사용자에게 알리는 원인도 바뀌었다 — 시스템이 준 실제 실패 원인을
  보존하고, 한도 초과가 아닌 실패를 한도 초과로 단정하지 않는다.
- **왜**: 예약이 0개인 기기에서 "예약 가능한 로케일 수(5개)를 초과했습니다"라는 오진이
  관측됐다. 원인은 두 겹이다. 실패 원인을 버리고 예약 목록에 없다는 사실만으로 한도 초과라고
  단정했고, 그 단정이 곧 세션 실패였다. 사용자는 해결할 수 없는 안내를 받고 녹취를 시작할 수
  없었다 — 정작 필요한 모델은 이미 설치돼 있었다. 회의는 시작 시각이 정해져 있어 이 대가가
  크다. 예약을 버리지 않은 이유는 그것이 세션 중 모델 회수를 막는 값싼 수단이기 때문이다:
  버리는 대신 실패를 치명적으로 다루지 않는 쪽으로 옮겼다.
- **측정으로 좁혀진 것**: **예약 없이도 파이프라인이 조립된다** — 예약 0개 상태에서 최적
  오디오 포맷 질의가 `16000 Hz, Int16`을 반환하고 분석기 준비도 성공했다. 그러므로 예약
  실패는 전사 불가와 동의어가 아니다. 한도는 **앱 단위**로 계산된다 — 한 앱이 5개를 채운
  상태에서 다른 앱이 추가 예약에 성공했다. 이 앱은 최대 2개만 필요하므로 단독으로는 한도에
  닿을 수 없다. 한도 초과의 실제 에러는 `SFSpeechErrorDomain` 코드 11
  ("Too many allocated locales, 5 maximum.")로 구분 가능하다. 예약은 **프로세스 수명을
  넘어 남는다** — 한 실행이 예약한 로케일이 종료 후 별개 실행에서 그대로 조회됐고, 이것이
  잔여 예약 회수가 필요한 이유다.
- **무효가 된 것**: "이전 세션이 남긴 예약 때문에 시작이 실패할 수 있다"는 Risk. 앱이 잔여
  예약을 스스로 회수하고, 회수가 통하지 않아도 모델이 설치돼 있으면 진행하므로 더는 시작을
  막지 않는다. 대신 예약 없이 진행한 세션에서 모델이 회수될 수 있다는 대가가 새로 생겼다.
